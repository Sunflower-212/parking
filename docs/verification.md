## 2026-10 全面优化验收

本节覆盖本轮改造，前文为历史版本记录。后端 36 项测试在 UTC JVM 下通过，其中包括真实 MySQL/Redis 的业务回归、权限竞争、并发会员/支付、预约取消/入场/过期竞争、旧消息、缓存故障及迟到回填。前端 2 项 HTTP 错误测试、5 项请求/组件/坐标测试通过，`npm ci` 和生产构建通过。

Chromium 4 项端到端验证覆盖超级管理员、普通管理员和用户：用户搜索与表单校验、平台页面权限、用户预约/刷新/取消、取消历史状态、第三方关闭提示，以及 375/768/1440 宽度无页面横向溢出。高分屏（DPR 2）下实际缩放、拖动地图后，点击仍选中正确车位。测试使用专用账号和 `parking-verification` 项目，不写入日常数据。

`test-migration.py` 验证全新结构、旧预约关联回填、歧义中止与数据保留，以及索引迁移重复执行、复用不同名称的等效索引。车位唯一索引按楼层顺序复用，移除被复合索引覆盖的单列索引，不删除业务记录或外键约束。

`test-service-recovery.py` 实际停止缓存 Redis 后读取仍成功；停止状态 Redis 时返回 503，恢复后相同 Token 继续有效；重启 MySQL、后端和 Nginx 后，专用测试记录及登录状态保留。

最终生产镜像已部署到本机 `http://localhost:8088`。升级前停止前后端，保存新的 MySQL 完整备份及停止状态下的 Redis 数据副本，保留旧应用镜像；执行索引迁移后重建服务。升级前后八张业务表的记录数一致，管理员登录、统计与默认关闭的第三方能力正常；再次重启前后端后，相同 Token 及业务记录仍保留。备份仅保存在本地已忽略的 `.work`，未上传公共仓库。

压力测试使用独立百万数据集，前后版本采用相同持久连接客户端。最初的短连接优化版测试因 Windows 临时端口耗尽失效，已排除并重新测试；不能将该轮正常请求的低耗时当作通过结论。最终三轮结果、资源用量、查询计划和未达标项目见[性能报告](performance-report.md)。
