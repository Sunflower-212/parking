# 本轮Java后端简历项目亮点

以下表述使用本轮实际完成的同场对照；可按简历篇幅选用。测试为独立模拟数据、单机Docker部署，不代表真实生产在线用户数或容量上限。

## 可直接使用

- 基于Spring Boot、MySQL和Redis优化停车预约事务，采用停车场资料共享锁、16桶强一致余位计数及事务前全局有界准入；在100万订单、100万入场记录、100 VU混合负载下，将三轮平均吞吐从400.16提升至1669.56请求/秒（提升317.22%），采样1,502,604次请求未出现非预期错误。
- 将容量更新收敛至事务末尾，保留用户/车位唯一约束与统一锁顺序；预约P95（三轮中位数）由888.83ms降至248.14ms，取消由894.74ms降至247.54ms，同时用户订单和楼层查询P95分别保持在2.16ms、3.73ms。
- 通过事务Outbox、RabbitMQ持久化消息、Publisher Confirm与手动ACK实现幂等后台任务及死信重放；在100 VU业务负载下，三次10万用户导出任务受理耗时12.15–15.75ms，文件就绪耗时458.00–1179.00ms，真实验证Broker停机期间预约可用及重启后任务恢复。
- 基于Redisson延迟队列、持久化事件表及完成事件快速确认优化预约到期处理；在60分钟、100 VU稳态测试中完成7,137,319次采样请求，两批共40条真实30分钟预约全部释放，数据库容量及占用关联核对无差异；通过61项后端回归，覆盖并发、权限、重复支付和中间件故障。

## 指标解释与复现

- 主对照每版100 VU、预热120秒、采样300秒、3轮；80%读取操作选择、20%预约选择，成功预约配对取消。候选实际HTTP写比例为33.33%。
- P95采用三轮各自P95的中位数，完整报告列出每一轮；不把中位数称为合并请求的总体P95。
- 对照1867459描述本轮收益；相对同场21d3012平均吞吐提升241.67%。原始版历史数据另见旧报告，不跨测试批次计算累计倍数。
- 百万数据是独立生成的历史记录，10万账号是模拟用户。分页主要测第1页20条，不能外推深分页、任意包含搜索或生产用户量。
- RabbitMQ的3次导出耗时是观测区间，样本不足以宣称导出P95；前台接收任务与文件生成完成是两个指标。预约吞吐提升来自事务设计，不能归因于RabbitMQ。
- 60分钟测试只跑1轮；40条到期探针与持续预约/取消负载分别记录。结束时的数据库一致性快照不代表对全过程做了连续快照验证。
- 复现：从对应Git提交构建历史镜像，准备隔离fixture后运行 `python scripts/run-round3-matrix.py`；消息成本和锁诊断命令见本轮完整报告。
